# Publish IINA releases from main

After CI passes on a merge to `main` that changes distributable plugin files or release automation, automatically increment the patch version and `ghVersion`, build a `.iinaplgz` asset, and create the GitHub release. Publish its `Info.json` and package version back to `main`, which IINA 1.5.0 checks for updates, and retain the packaged `master` mirror because IINA 1.4.4 checks `master/Info.json`. Metadata publication rebases onto newer source commits and uses non-force pushes so it cannot replace concurrent work; documentation-only changes run CI without publishing a release.
